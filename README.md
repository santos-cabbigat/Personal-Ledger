# Personal & Business Ledger

[Open the ledger](https://santos-cabbigat.github.io/Personal-Ledger/) or [try the sample-data preview](https://santos-cabbigat.github.io/Personal-Ledger/?preview=1). The main link opens the Google deployment. The preview lasts for the current session.

## Use a Google Sheet

Each person signs in with their own Google account. **Connect Google Drive** creates or reconnects their own ledger in **My Drive → Personal & Business Ledger**. The original owner keeps the existing workbook. To use one shared database, its owner shares the spreadsheet with each contributor as an Editor. In Settings, contributors choose **Open existing ledger** and paste the same spreadsheet URL. The app refreshes when reopened or brought back to the foreground with the main screen visible. **Refresh** reads the latest Sheet immediately.

In **Accounts**, enter a unique code, name, classification, optional parent code, and use (`Posting` or `Group`). On **Journal**, use the calendar for Date, the Book dropdown, and a posting account from the code or name list. On new lines, selecting the name fills its code and classification. The original bound Sheet also fills the name when a code changes. Enter adjacent lines for each transaction. Use Date, Book, Description, Account code, Debit or Credit, and optional Project and Category names. Add a book in app Settings with **Add book type**, or enter a name in **Settings → Book types** (column F). **Journal → Find entry ID** in the app opens an existing entry. In the Sheet choose a posted ID in **Journal!P2** and follow the row link in Q2. For blank Entry IDs, keep each balanced transaction together. Date, book, description and project can be entered once within that group. In the original workbook, select a transaction row and use **Ledger → Post selected journal entry**. You can also refresh the app, open the transaction, then select **Review & post sheet entry**. Newly created workbooks receive the same dropdowns and lookup formulas. Posting for those workbooks uses the app because they do not contain a bound script. The app fills in its permanent ID, account details, and the signed-in poster. Incomplete groups have a row-specific message. Drafts appear in Journal and are excluded from reports until posted. To change a posted item, open **Journal → entry → Edit entry**.

All books in the same spreadsheet share a daily series: `YYMM-DDA001` through `YYMM-DDA999`, then `B001`; `Z999` rolls to `AA001`. IDs use the transaction date. Edits keep the original posted ID and Gmail. Backup the workbook from Settings as Excel; Journal, Accounts and Reports offer CSV downloads. Report CSV uses the same book, project, category and date filters as the on-screen report.

## Deploy an update

Use the [two-file installer](https://santos-cabbigat.github.io/Personal-Ledger/copy-script.html) in the existing Apps Script project. When opened with a workbook ID in its URL fragment, the installer binds the legacy workbook without including its ID in the public repository. The installer contains both the complete Code.gs and the manifest. The manifest enables the advanced Sheets v4 and Drive v3 services. If you use a standard Cloud project, enable their APIs there too. Keep the deployment running as the user accessing the app. Google handles sign-in in the browser. Anyone using a future Android wrapper must sign in through the system browser or a browser-backed custom tab.

Edit `docs/index.html` and `apps-script/Code.gs`, then run `node scripts/build.mjs` to regenerate the Apps Script interface, the preview's matching ID generator, and the single-file script installer. The split Apps Script sources also support a Sheet-bound deployment initialized from the Ledger menu.

Column R in Journal stores a receipt or transfer reference as text, including leading zeros. A blue first row separates each transaction. Lines sharing a manual Entry ID may use different descriptions and references. Posting a balanced Sheet draft retains a correctly dated manual ID and records the signed-in poster. Settings lists IDs directly from Journal.
